# M3.4 Determinism Audit

Source-of-truth audit of every `Utc::now()` / `SystemTime::now()` call site in the
Cube Store metastore. Classifies each as one of:

- **W** — _Wrapper_. Historic constructor stamps `Utc::now()` but the leader path
  uses a `_pure` / `_with_now` variant; or the leader builds the row and ships it
  as a blob through Raft.
- **P** — _Persistent leader-stamped_. Site lives on the propose side
  (`RaftMetaStore`), resolves `Utc::now()` once on the leader and ships
  `assigned_now_millis` through the Raft log.
- **T** — _Transient / local_. Read-only filter, span/trace start time, secondary
  index local cache, snapshot housekeeping. Does not affect replicated state.
- **G** — _Gap_. Persistent state stamped on each replica's local clock —
  determinism violation.

**Result: 0 gaps.** The audit was performed against [agriev/cube@m3.4-finalize]
(branch off `ha-main`).

## Apply-path coverage matrix (leader-stamped writes)

Every persistent write whose row carries a `DateTime<Utc>` field flows through
`assigned_now_millis` over Raft and lands via a `_with_now` apply call:

| Trait method on `RaftMetaStore`                  | `MetaCommand`                          | Apply call (`rocks_apply.rs`)                       |
|---|---|---|
| `create_table`                                   | `CreateTable { ..., assigned_now_millis }`               | `create_table_with_now`                             |
| `create_chunk`                                   | `CreateChunk { chunk_blob }` (whole-row blob; M3.4.a)    | `insert_chunk_pre_built`                            |
| `deactivate_chunk`                               | `DeactivateChunk { ..., assigned_now_millis }`           | `deactivate_chunk_with_now`                         |
| `deactivate_chunks`                              | `DeactivateChunks { ..., assigned_now_millis }`          | `deactivate_chunks_with_now`                        |
| `start_processing_job`                           | `StartProcessingJob { ..., assigned_now_millis }`        | `start_processing_job_with_now`                     |
| `update_heart_beat`                              | `UpdateHeartBeat { ..., assigned_now_millis }`           | `update_heart_beat_with_now`                        |
| `update_status`                                  | `UpdateStatus { ..., assigned_now_millis }`              | `update_status_with_now`                            |
| `create_replay_handle`                           | `CreateReplayHandle { ..., assigned_now_millis }`        | `create_replay_handle_with_now`                     |
| `create_replay_handle_from_seq_pointers`         | `CreateReplayHandleFromSeqPointers { ..., assigned_now_millis }` | `create_replay_handle_from_seq_pointers_with_now` |

`add_job` and `insert_chunks` use the whole-row-blob pattern (M3.4.a) — the row
is built on the caller, the leader proposes the serialized blob, replicas
deserialize the same bytes and insert.

The LRU case (189) was the original "suspect" from the parked audit. Confirmed
not a gap: the RocksDB primary key/value is determined by the row passed to
`update_with_fn` (which is leader-stamped through `_with_now`); the secondary
index value is regenerated locally on each replica from that primary. Different
LRUs = different *eviction order*, but the same logical contents.

These run inside `read_operation_out_of_queue` — they scan rows and filter by
elapsed time. They never write back. Each replica produces a *result list* that
may differ slightly across replicas (because each clock is different), but
that's already how non-HA reads work — the result is consumed by the caller, not
written to metastore.

## Out-of-scope sites (informational)

`metastore/rocks_fs.rs:225` — `SystemTime::now()` for snapshot housekeeping
cutoff. **T**: per-replica local file-system maintenance, deletes old snapshot
files. Replicas independently clean their own remote-fs snapshot directories;
the action does not flow through Raft.

## Conclusion

All 34 metastore `Utc::now()` sites are classified. Zero gaps remain. The
chunk-blob (M3.4.a) and `_with_now` (M3.4.b/c/d) patterns together cover every
persistent write path in the leader-stamp flow.

The remaining cleanup is documentation: the stale "_Determinism caveat (still
unfixed)_" header in `raft/raft_meta_store.rs` (lines ~35-50) and the matching
warnings in `config/mod.rs` (the boot-time `M3.4 has landed` log) — both
predate M3.4.b/c/d landing and contradict the current code. Phase 4 of the
finalize plan removes them.
